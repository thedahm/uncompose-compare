# Uncompose Compare v0.1.0

First release. `uncompose-compare` loads exactly two audio files as candidates,
lets you listen to the same moment in either with zero drift, loop the region
where the difference lives, write down what you hear as you hear it, pick a
winner, and keep a trustworthy, immutable record of the whole evaluation.

## What it does

- `uncompose-compare <A> <B>` (bare files) and, through
  [`uncompose-project`](https://github.com/thedahm/uncompose-project) refs,
  `uncompose compare --project . <ref> <ref>` — standalone and through root
  dispatch (`uncompose compare`).
- A consolidated workbench with synchronized SRC/A/B lanes, waveform/loudness/
  spectral views, stem-targeted timestamped pins, and an editable engraved
  verdict with confidence stars.
- `--blind` conceals which candidate is which behind shuffled labels, with the
  saved record correctly reconnecting the labels afterward.
- Optional, off-by-default `--loudness-match` (gain-only BS.1770
  attenuate-to-quietest).
- A privacy-first local server: 127.0.0.1, ephemeral port, session token, no
  network I/O, blanket no-store.
- The written comparison record is immutable — one write, never mutated — and,
  in project mode, auto-imports into the manifest as an evaluation at conclude.
- Ships as a Linux `maturin` wheel with the frontend embedded (Node only at
  build time): `pip install uncompose-compare`.

## Schema policy

The comparison record's `schema` field carries a major-only identifier URL,
`https://uncompose.org/schemas/compare/v0/uncompose.compare.schema.json`,
compared by exact string match. `v0` covers this entire pre-1.0 period: purely
additive optional fields never move the URL, but a breaking change (a field
removed, renamed, retyped, or repurposed) can ship between releases without one
either — that's what `v0` signals. There is no migration machinery in v0.1: if a
record written by an older v0.1.x release stops validating against a newer one,
the remedy is to regenerate it or hand-edit it to match. See
[uncompose#64](https://github.com/thedahm/uncompose/issues/64) for the full
policy and [ADR-0002](../adr/0002-comparison-record-lifecycle.md) for how this
repo adopted it.

See [known limitations](../known-limitations.md) for the full list, including
